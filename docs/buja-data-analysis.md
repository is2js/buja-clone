# 부자 원본 사이트 데이터 구조와 계산 방식

조사일: 2026-11-04 (한국 시간). 대상은 [부자 부동산자본주의](https://buja.buildlab.im/)의 로그인 없이 접근 가능한 HTML, JavaScript, 정적 데이터와 일부 공개 URL이다. 이 문서는 **현재 클론의 더미 데이터 설명이 아니라 원본에서 관찰한 구현 분석**이다. 파일이 바뀔 수 있으므로 아래 수치와 응답은 조사 시점의 스냅샷이다.

**확인 범위:** 브라우저에 전달된 코드·데이터·화면 문구와 직접 조회한 URL만 확인했다. 수집기 원본, 서버 DB 구조, 배치 실행 이력, API 승인·요금 및 개별 거래 원본의 품질은 확인하지 못했다. 코드 주석과 화면이 주장하는 데이터 출처·갱신 시각은 그 주장 자체로 기록하며, 실제 운영 파이프라인의 정상 실행을 보증하지 않는다.

## 1. 데이터 흐름과 화면

원본은 초기 HTML에서 다음 파일을 순서대로 읽는다. `geo.js` → `market.js` → `news.js` → `data.js` → `sample.js` → `app.js`. 앞의 파일이 `window.BUJA_*` 전역 객체를 만들고, `data.js`가 이를 조합해 지역 모델을 구성한 다음 `app.js`가 지도·랭킹·시장·GTX·상세 화면을 그린다. 초기 시장·뉴스 데이터는 JSON API 요청이 아니라 JavaScript 안에 담긴 정적 산출물이다. 개별 거래·건물 목록은 이후 필요할 때 별도 JSON을 지연 로드한다. [HTML](https://buja.buildlab.im/) · [데이터 조합](https://buja.buildlab.im/js/data.js) · [화면](https://buja.buildlab.im/js/app.js)

| 데이터 | 공개된 입력·키 | 사용하는 곳 | 확인할 한계 |
|---|---|---|---|
| 행정 경계 | `BUJA_GEO`: 시도·구·동 코드, SVG 경계, 박스와 중심점 | 지도 색상·검색·지역 클릭·GTX 표시 | 행정동 경계와 거래의 법정동은 동일하지 않음 |
| 시세·거래 통계 | `BUJA_MARKET`: 유형별 요약과 월별 배열 | 지도 지표, 순위, 지역 상세, 시장 | 실제 수집기와 통계 산출 파이프라인은 미확인 |
| 기사 | `BUJA_NEWS`: 시군구별 제목·링크·분류 | 지역 상세 뉴스 | 자동 키워드 분류이며 기사 판단 검증 필요 |
| GTX | `data.js`의 수동 노선·역·상태와 `geo.js` 위치 매핑 | 노선도, 역 목록, 점수 | 실제 거리나 도보 시간을 산출하지 않음 |
| 개별 거래·건물 | 캐시 브랜치의 거래 JSON·건물 인덱스·좌표 파일 | 상세 거래, 건물 검색·지도 핀 | 조사한 일부 URL 404; 전체 존재 여부는 미확인 |
| 리뷰 | `/api/reviews`, 샘플은 `BUJA_SAMPLE` | 건물 상세 | 조사 요청에서 DB 미설정 응답; 서버 구조 미확인 |

## 2. 행정 경계와 지도

[geo.js](https://buja.buildlab.im/js/geo.js)는 `scripts/buja-geo.mjs`로 생성했다고 명시하며 경계 원천으로 통계청 행정동 경계 및 [vuski/admdongkor](https://github.com/vuski/admdongkor)의 `ver20261001`을 표시한다. 파일 최상위 키는 `w`, `h`, `sido`, `gu`, `dong`, `stations`, `stationXY`다. 시도와 시군구는 표시명과 범위(`b`)를, 구·동 경계는 SVG path `d`와 중심·상위 코드 등을 갖는다. 역 매핑은 노선-역 이름을 키로 행정동 코드와 지도 좌표를 연결한다.

조사본은 **시도 16개 그룹, 구 256개, 동 3,559개**이며 `전남광주`가 한 그룹으로 되어 있다. 이는 표시용 가공 데이터의 구성이며 현재 행정 체계의 시도 개수와 동일하다는 뜻은 아니다. 화면은 SVG 행정동 경계에 지표별 색을 칠하고, 구 경계와 GTX 선·역을 겹친다. 확대 시 외부 배경 타일을 표시하며, 건물 위치가 있는 경우에만 건물 핀을 만들도록 설계돼 있다. 외부 타일이나 경계 데이터는 각 원천과 중간 가공물의 이용 조건을 검토해야 한다.

시군구 통계는 시군구 코드로 연결하지만, 동별 통계는 `normDong()`으로 이름에서 숫자·동/가 등의 접미사를 제거한 문자열을 이용한다. 예를 들어 행정동과 법정동의 비슷한 이름을 맞추기 위한 휴리스틱이며, **경계가 같거나 거래가 실제 해당 행정동 내부에 있다고 보장하지 않는다.** 같은 정규화 이름에 여러 행정동이 대응될 수도 있다. 행정구역 개편·명칭 변경과 코드 버전 차이도 별도로 검증해야 한다. [데이터 결합 코드](https://buja.buildlab.im/js/data.js)

## 3. 시세와 거래 데이터

[market.js](https://buja.buildlab.im/data/market.js)의 주석과 원본 화면은 국토교통부 실거래가 공개 API를 원천으로 설명한다. 공공데이터포털의 [아파트 매매 API](https://www.data.go.kr/data/15126469/openapi.do)와 [아파트 전월세 API](https://www.data.go.kr/data/15126474/openapi.do)는 해당 유형의 공식 자료 예시다. 원본이 실제 어떤 API 버전·호출 조건을 사용했는지 수집기 없이 확정할 수 없다.

### 최상위 구조

- `asOf`: 거래 기준월. 조사본은 `2026.10`.
- `updatedAt`: 산출물 갱신 시각. 조사본은 `2026-11-01T19:01:07.649Z` = 한국 시간 2026-11-02 04:01:07.
- `apis`: 8개 원천별 `label`, `from`, `to`, `months`, `deals3m` 요약.
- `gu`: 시군구 코드별 유형 요약과 시계열의 압축 배열.
- `dong`: 시군구 코드 → 정규화한 법정동 이름 → 유형별 요약.
- `signals`: 개별 거래 기반 신고가·하락 단지 등 시장 신호. 필드와 전체 생성 조건은 수집기 없이 확인할 수 없다.

`apis`에는 아파트(`apt`), 연립·다세대(`rh`), 단독·다가구(`sh`), 오피스텔(`offi`) 각각의 매매(`Trade`)·전월세(`Rent`)가 있다. 조사본에서 아파트 매매 범위는 2024.06~2026.10, 전월세는 2025.04~2026.10이고 두 유형 모두 최근 3개월 건수 요약을 포함한다. 다른 유형의 확보 월수는 서로 다르므로 같은 기간이 모두 채워져 있다고 가정하면 안 된다.

### 압축 배열 해석

`gu[코드]`의 인덱스는 다음 순서다. 각 요약은 없는 경우 비어 있을 수 있다.

| 인덱스 | 내용 |
|---:|---|
| 0~1 | 아파트 요약, 연립·다세대 요약 |
| 2~3 | 아파트 월별 시계열, 연립·다세대 월별 시계열 |
| 4~5 | 단독·다가구 요약, 오피스텔 요약 |
| 6~7 | 단독·다가구 월별 시계열, 오피스텔 월별 시계열 |
| 8 | 월별 아파트 거래량 시계열 |

유형 요약 배열의 필드 순서는 `[price, yoy, tx, txYoy, jeonse, ch1, ch3, ch6, peak]`이다. `price`는 3.3㎡당 만원, `tx`는 최근 3개월 거래 건수, 나머지는 퍼센트다. 각각 1년 가격 변동, 거래량 전년비, 전세가율, 1·3·6개월 가격 변동, 최고가 대비 변동을 의미한다. `dong[구코드][정규화명]`은 `[아파트, 빌라, 단독, 오피스텔]` 요약이다. `data.js`의 `mk()`는 첫 가격 값이 없는 요약을 `null`로 취급한다. [구조 해석 코드](https://buja.buildlab.im/js/data.js)

화면 설명에 따르면 아파트 시세는 최근 3개월 전용면적 3.3㎡당 실거래 중앙값이며 단독·다가구는 연면적 기준을 쓴다. 전세가율은 최근 6개월 전세 보증금과 매매가의 ㎡당 중앙값 비율로 설명된다. 계약일 기준으로 해제 거래는 통계에서 제외하고 중복을 제거한다고 화면에 적혀 있다. 개별 상세 차트는 거래금액/면적 × 3.3058의 월 중앙값을 쓰며 월 거래가 3건 미만이면 값을 비운다. 수집기 내부의 모든 표본 조건과 환산 방식까지 독립적으로 검증한 것은 아니다. [화면 코드](https://buja.buildlab.im/js/app.js)

원본 화면은 1년 변동을 비교하는 두 기간 모두 거래가 30건 이상이고 변동이 ±40% 범위일 때만 사용한다고 설명한다. 신고 지연과 표본 구성에 따라 최근 수치와 중앙값은 바뀔 수 있다. 출처는 실제 거래이지 호가나 감정가가 아니라고 설명하지만 원본 수집·정정 이력을 확인하지 못했다.

## 4. 동 대체값과 차트

`pick()`은 동 이름으로 찾은 유형 통계가 있으면 이를 우선 사용하고 `from: 'dong'`을 붙인다. 동의 `yoy`, `txYoy`, `ch1`, `ch3`, `ch6`, `peak`가 `null`이면 해당 필드만 시군구 값을 가져온다. 동 유형 데이터 자체가 없으면 시군구 유형 요약 전체를 `from: 'gu'`로 사용한다. 둘 다 없으면 `null`이다. 따라서 **한 지역 상세에 같은 동의 값과 상위 구 대체값이 섞일 수 있다.** `own` 및 `yoyFrom`은 일부 항목의 출처를 구별한다.

월별 차트는 최대 36개월에 맞춰 앞쪽 부족분을 `null`로 채운다. 아파트·빌라의 동 차트는 독립적인 동별 월 시계열을 불러오는 것이 아니라, **시군구 월별 시계열 × (현재 동 시세 / 시군구 시계열 마지막 값)**으로 비례 변환한 값이다. 마지막 값이 없거나 0이면 차트가 없다. 단독·오피스텔과 아파트 거래량 시계열은 시군구 흐름을 그대로 쓴다. 이 그래프를 실제 동별 월별 집계로 표기하면 안 된다. [결합·차트 코드](https://buja.buildlab.im/js/data.js)

## 5. 지도 지표, 랭킹, 시장

지도와 랭킹은 종합점수, 아파트 시세, 1·3·6개월 및 1년 변동, 3개월 거래량, 거래량 전년비, 아파트·빌라·오피스텔 전세가율, 최고가 대비 등 12개 지표를 사용한다. 점수·가격·거래량 같은 순차 지표는 같은 시도의 동 값을 20·40·60·80% 분위 경계로 나눠 5색으로 표시한다. 변동률은 음수·중립·양수의 별도 구간, 전세가율과 최고가 대비는 각각 별도 기준을 적용한다. 결측은 데이터 없음으로 표시한다. [지표와 색상](https://buja.buildlab.im/js/app.js)

랭킹은 동/구와 지역 및 지표에 따라 정렬한다. 시장 화면은 거래량 급증·급감, 3개월 상승·하락, 1년 상승, 최고가 대비 하락, 개별 거래 기반 신고가 등의 목록을 구성한다. 동 시장 목록의 일부 지표는 상위 구 대체값이 아니라 해당 동에서 직접 계산된 값만 포함하도록 `own`을 확인한다. 구 점수는 동 점수를 평균한 값이 아니라 구끼리 별도로 계산한다.

## 6. 종합점수 계산

[점수 코드](https://buja.buildlab.im/js/data.js)는 전국 동끼리·구끼리, 그리고 각 시도 내 동끼리·구끼리 별도 비교한다. 아파트 가격이 없는 지역은 계산과 순위에서 제외한다. 비교 집단 내 각 항목의 값별 백분위를 구하며 동점은 해당 값 구간의 가운데 순위를 쓴다.

| 항목 | 가중치 | 높은 점수 방향 |
|---|---:|---|
| 아파트 시세 수준 | 40 | 높을수록 높음 |
| 아파트 1년 가격 흐름 | 25 | 높을수록 높음 |
| GTX | 15 | 동에 역 2, 같은 구에만 역 1, 없음 0 |
| 최근 3개월 거래 활력 | 10 | 거래 수가 많을수록 높음 |
| 전세 안정 | 10 | 전세가율이 낮을수록 높음 |

각 백분위를 0~100으로 반올림해 가중 평균한다. 항목이 `null`이면 그 항목을 빼고 **남은 가중치의 합으로 나눈다.** 종합값으로 정렬하고 같은 종합값에는 같은 순위를 부여한 뒤, 순위 백분위를 최종 점수로 바꾼다. 전국 점수는 `63 + 37 × 순위백분위`, 시도 점수는 `시도 바닥 + (100 − 바닥) × 순위백분위`이며 둘 다 소수 둘째 자리다. 시도 바닥은 전국 순위 백분위의 집단 중앙값을 사용해 63~66 사이로 정한다. 등급은 순위/집단 수 기준 S 상위 10%, A 30%, B 50%, C 70%, D 나머지다. 이는 **상대적인 순위 표현**이며 절대 가치·투자 수익률을 예측하는 모델이 아니다.

GTX 점수는 역까지의 거리 계산이 아니다. 역이 같은 동 또는 같은 구에 속하는지의 매핑만 사용하며 노선의 계획·공사·운행 구분이 거리나 이용 가능성의 검증을 대신하지 않는다.

## 7. 뉴스와 GTX

[news.js](https://buja.buildlab.im/data/news.js)는 `asOf`, `src`, `gu`를 갖고, 구별 기사 항목은 `t` 제목, `u` URL, `d` 날짜, `s` 매체, `g` 호재 여부, `c` 분류, `k` 정규화 동 키로 구성된다. 원본 화면은 제목에 지역명이 있는 기사와 제목 단어를 이용해 호재·악재를 분류한다고 설명한다. `data.js`는 해당 동 키가 맞는 기사 다음에 나머지 구 기사를 붙인다. 기사 원문 사실 검증이나 분류 정확도는 확인되지 않았다.

조사본 `news.js`는 `src: 'google'`이며 주석도 구글 뉴스 검색이라고 되어 있지만, `data.js`의 예전 주석은 네이버 검색 API라고 되어 있다. 이는 **주석과 현재 산출물의 불일치**다. 조사본 기사 산출시각은 `2026-11-01T19:01:28.932Z`(한국 시간 2026-11-02 04:01:28)다. 당시 실제 수집 방법이나 현재 뉴스 계약은 이 사실만으로 확정할 수 없다.

GTX A·B·C 노선, 역 이름, 상태와 설명은 `data.js`에 수동 정의돼 있으며 `geo.js`의 역-행정동 매핑으로 상세를 연다. 화면의 역 주변 평균은 역이 속한 행정동 전체 기준이며 실제 역 반경이나 도보 거리 기준이 아니다. 계획과 개통 상태는 변할 수 있으므로 공적 발표와 재확인이 필요하다.

## 8. 건물·개별 거래·리뷰

화면 코드는 `https://raw.githubusercontent.com/jamesunny/casino/buja-data-cache/`를 기준으로 `deals/{kind}/{시군구}.json`, `props/index.json`, `props/map/{시군구}.json` 등을 필요할 때 불러오고 결과를 메모리에 캐시한다. 거래 파일은 JSON의 `m` 월별 값을 펼친다. 검색 인덱스는 유형, 시군구, 건물 ID·이름, 법정동·지번·도로명, 최근 매매가·일자, 준공연도 순서의 압축 배열이다. 원본은 최근 13개월 신고 거래에 나타난 건물만 검색한다고 설명한다. [거래·검색 코드](https://buja.buildlab.im/js/app.js)

2026-11-04 직접 조회에서 [검색 인덱스](https://raw.githubusercontent.com/jamesunny/casino/buja-data-cache/props/index.json), [종로구 아파트 거래 예시](https://raw.githubusercontent.com/jamesunny/casino/buja-data-cache/deals/apt/11110.json), [종로구 좌표 예시](https://raw.githubusercontent.com/jamesunny/casino/buja-data-cache/props/map/11110.json)는 각각 HTTP 404였다. **이 세 경로의 당시 응답일 뿐 다른 지역·시점·서버 전체에 데이터가 없다는 뜻은 아니다.** 프런트는 404를 `none`, 그 밖의 실패를 `err`로 구분한다.

건물 상세의 사진, 세대수, 주차·난방·관리비, 지오코딩, 학교·대중교통·편의시설, 실제 거리·길찾기 등은 해당 API를 아직 적용하지 않았다는 빈 상태를 보여준다. 역의 동일 동/구 정보만으로 건물과 역의 거리를 추정하지 않는다.

실제 건물 리뷰는 `/api/reviews`에 GET/POST/PATCH/DELETE를 보내고 도움돼요·신고 액션도 요청하는 코드가 있다. 2026-11-04 비민감 테스트 GET `/api/reviews?property=apt%3A11110%3Asample` 응답은 HTTP 503, `configured:false`, DB 미연결 메시지였다. 서버 구현·저장 스키마·인증·다른 시점의 가용성은 확인하지 못했다. 샘플은 [sample.js](https://buja.buildlab.im/js/sample.js)의 가상 시군구 `00000`, 가상 건물·거래·리뷰를 사용하며 브라우저 메모리에서만 바뀌고 새로고침 시 사라진다.

## 9. 갱신, 불확실성 및 후속 연동

원본 화면은 매일 한국 시간 새벽 3시 갱신이라고 표시하고, `data.js` 주석은 GitHub Actions가 매일 갱신한다고 말한다. 조사 시점의 파일은 위 `updatedAt`을 갖는다. 그러나 **워크플로 파일과 실행 로그는 확보하지 못했으므로** 실행 주기·성공 여부·지연·복구 절차는 확인되지 않았다. 화면의 스케줄 설명과 확인된 산출물 시각을 동일한 증거로 취급하지 않는다.

현재 클론은 `public/data/demo.json`과 코드 기반 가상 수치만 사용한다. 원본의 실제 수집 파이프라인을 갖고 있지 않다. 향후 단계에서 검토할 사항은 다음과 같다.

1. 국토부 원천별 신청·승인, 키 보관과 호출량, 월별 페이징·수집·재시도, 신고 정정·해제 반영을 확인한다. 외부 서비스 키는 브라우저가 아니라 필요 시 FastAPI 등 서버 측에서 관리한다.
2. 행정동·법정동과 경계 버전을 명시적으로 매핑하고 이름 정규화의 충돌·미매칭을 추적한다. 지리정보 및 타일 출처·가공물 이용 조건과 배포 정책을 확인한다.
3. 수집 원본·집계 스냅샷·갱신 시각·표본 수·동/구 대체 출처를 보존하고, 실데이터·샘플·누락을 API 응답과 화면에서 구별한다. 차트 보정값은 원본 동별 시계열과 명확히 구별한다.
4. 점수의 비교 집단·가중치·결측 규칙과 기사 분류의 신뢰 한계를 버전 관리한다. 원본 규칙을 재구현할지 변경할지는 별도로 결정한다.
5. 건물 좌표, 기사 재배포, 리뷰 저장·인증·신고 및 운영 정책은 제공자와 서비스 설계가 확정된 뒤 개별 연동한다. 원본의 비공개 구현을 추정해 복제하지 않는다.

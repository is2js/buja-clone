## 집계 방법과 한계

- 2026-08~10의 아파트 거래금액 ÷ 전용면적 × 3.3058 중앙값을 `price`(만원/3.3㎡)로 표시한다. `transactions`는 해제 거래를 뺀 최근 3개월 신고 건수이고, `sampleCount`는 가격과 면적이 유효한 거래 건수다. 12개 월별 `series`는 각 월의 중앙값이며 `monthlyCounts`는 유효 표본 수다.
- 1개월은 최근 월과 전월, 3개월은 최근 3개월과 이전 3개월, 6개월은 최근 6개월과 이전 6개월의 중앙값 변화를 각각 표시한다. 양쪽 유효 표본이 각각 **30건 이상**일 때만 계산한다. `change1Samples`, `change3Samples`, `change6Samples`는 각 기간의 `current`와 `previous` 건수를 보존한다. 연간 동기 비교를 할 이전 연도 자료는 없으므로 `yoy`는 비운다.
- 전세가율은 최근 6개월의 전세 보증금/전용면적 중앙값을 같은 기간 매매 가격/전용면적 중앙값으로 나눈 참고 지표이며 두 그룹 유효 표본이 각각 30건 이상일 때만 계산한다. 전세 건수 `rentSampleCount`, 매매 건수 `jeonseSaleSampleCount`를 제공한다. `monthlyRentMedian`은 최근 3개월 월세 신고의 월세액 중앙값(만원)이고 `monthlyRentSampleCount`를 함께 둔다. 전세·월세는 별도 항목이다.
- 상업·업무용 집계는 제공된 전용/연면적에 거래금액을 나눈 참고 중앙값이며 단일한 상가 시세로 해석해서는 안 된다. 주용도와 물건의 구성이 다르고 전용면적과 연면적이 섞일 수 있다. 신고일 기준 공식통계와도 다르다.
- 공식 법정동 마스터의 전체 주소에 **정확히** 일치하는 거래만 법정동으로 연결한다. `리` 주소는 그 `읍`·`면` 상위 경계로 집계한다. 구 집계에는 이들 하위 지역의 거래를 함께 포함한다. 행정동별 거래는 도로명·지번에 따른 별도 공간 매칭이 검증되지 않아 제공하지 않는다. 경기도 거래의 모든 행은 구/법정동(또는 읍면 부모)으로 연결되었다.
- 업소 수는 소상공인 파일의 법정동·행정동·시군구 코드를 각각 사용하며 `categories`는 업종 대분류별 개수다. 법정 리 코드가 앱 목록에 없는 경우 상위 8자리가 정확히 일치하고 실제 읍·면 코드가 존재할 때만 해당 읍·면으로 집계한다. 직접 일치·리 상위 매핑·미연계를 진단에 별도로 기록한다. 특정 점포의 개인정보나 연락처는 JSON에 넣지 않는다. 당일 실제 영업 상태를 보장하지 않는다.

## 재생성 및 후속 수집

1. 공식 자료제공 화면에서 위 두 지역·세 거래 유형을 기간별로 다운로드한다(시도별 한 번에 최대 1년). 로컬 작업 디렉터리에 각각 `11000-apt-sale.tmp`, `11000-apt-rent.tmp`, `11000-commercial-sale.tmp`, `41000-apt-sale.tmp`, `41000-apt-rent.tmp`, `41000-commercial-sale.tmp`로 저장한다. 내용은 CP949 CSV다.
2. `python scripts/aggregate-transactions.py <CSV-디렉터리> --as-of 2026-10`을 프로젝트 루트에서 실행한다. `--as-of YYYY-MM`을 새 자료의 마지막 **완료된 계약월**로 바꾸면 그 달을 포함한 12개월을 집계한다. 이 옵션을 생략하면 기존 결과의 기준월을 재사용하며 새로운 월이 발견되면 중단한다. `.tmp` 또는 `.csv` 확장자를 사용할 수 있다.
3. 상권 ZIP은 `python scripts/aggregate-shops.py <ZIP-경로> --as-of 2026-09-30`으로 직접 스트리밍 집계한다. 실제 원본에 명시된 기준일을 `--as-of YYYY-MM-DD`로 기입한다. 날짜 없는 ZIP 이름에서 기준일을 추측하지 않는다.
4. 두 집계기는 필수 파일과 헤더, 비어 있는 결과를 확인하고 검증 실패 시 기존 JSON을 보존한다. 실거래는 6개 파일의 서울·경기 일치와 12개월 존재를 확인한다. 실행 시 입력·매칭·미연계 건수를 보고하며 JSON 교체는 임시 파일을 통한 원자적 변경이다. `--output <경로>`로 본 결과와 분리해 검증할 수 있다. 실제 자료 자체의 누락이나 최신성은 제공처 기준일과 별도로 확인해야 한다.
5. 지속 갱신은 나중에 승인받은 [아파트 매매 API](https://www.data.go.kr/data/15126469/openapi.do), [아파트 전월세 API](https://www.data.go.kr/data/15126474/openapi.do), 상업·업무용 API 및 [상권 API](https://www.data.go.kr/data/15012005/openapi.do)로 전환할 수 있다. 키는 비공개 수집 환경에만 보관하고 JSON만 사이트에 제공한다. 정정·해제, 할당량·승인·페이징을 점검한다.

## 2026-11-04 상권 코드 정합성 재검토

기존 집계는 법정리 업소를 상위 읍·면에 합산하지 않아 경기 읍·면 통계가 누락됐습니다. 공식 2026-09-30 ZIP을 다시 받아 해당 리의 상위 읍·면 코드가 현존하는 경우에만 122,103건을 합산했습니다. 종로구 세종로도 현존 법정동 목록에 포함해 상권 141건을 복원했습니다.

재집계 후 서울 법정동 합은 시군구 합과 일치합니다. 경기는 666,254건 중 542,393건이 법정동 직접 일치, 122,103건이 리→읍·면으로 연결되었고 1,758건은 법정동에 연결되지 않았습니다. 시군구와 법정동 합 차이는 화성시 동탄구 1,757건, 부천시 소사구 1건입니다. 화성시의 미매칭 업소에는 현행 법정동 목록에 없는 원천 코드가 사용되어 있으므로 임의로 배정하지 않았습니다. 영향을 받는 구의 법정동 상권 화면에는 집계 불완전 가능성을 표시합니다. 시군구·행정동 상권 집계는 각각 원본 코드 기준으로 별도 집계합니다.

점수는 `src/scoring.js`의 `buja-partial-v1`로 앱 기동 시 다시 계산합니다. 확보한 아파트 가격·거래량·전세가율이 각각 필요한 표본을 충족할 때만 같은 시도·지역 유형·자료 출처와 시점의 집단 안에서 비교합니다. 1년 가격 흐름과 GTX는 이 버전에서 사용하지 않습니다. 자료가 추가되더라도 자동으로 원본 5항목 점수로 전환되지 않으며, 새 지표의 품질과 비교군을 검증한 후 별도 버전으로 변경해야 합니다.


## 전국 아파트 매매·전월세 보충 자료 (2026-11-04)

국토교통부 실거래가 공개시스템 조건별 자료제공에서 서울·경기 외 14개 시도의 아파트 매매와 전월세 각 1개씩, 총 28개 CSV를 수집했다. 계약일 범위는 2025-11-01~2026-10-31이며 인천은 매매 30,995건, 전월세 62,511건이었다. 현재 시스템은 전남광주통합특별시를 코드 12000으로 제공한다. 상업·업무용과 상권 자료는 새로 수집하지 않았다. 계약일 자료는 신고 지연·정정·해제로 변하며, 외부 공개 시에는 제공기관의 신고일 기준 공식통계 안내를 따라야 한다.

각 입력은 `<시도 5자리>-apt-sale.csv`, `<시도 5자리>-apt-rent.csv`로 저장하고 `python scripts/aggregate-other-transactions.py <입력 디렉터리> --as-of 2026-10`으로 `transactions-other.json`을 갱신한다. 각 시도의 원천 파일과 모든 12개월, 헤더 및 지역을 검증하며 실패하면 기존 결과를 보존한다. 법정동 코드표에서 주소가 정확히 일치할 때만 법정동으로 집계하고, 법정리는 정확하게 일치하는 읍면으로 합산한다. 잘못된 법정동을 유추하거나 행정동 점수로 대체하지 않는다. 로더는 기존 서울·경기와 전국 보충 파일을 합치되 충돌 시 기존 스냅샷을 우선하며, 점수는 각 지역의 출처·기간별로 따로 비교한다.

# 전국 3D 건물 자료 확인

조사일: 2026-11-05, 재확인: 2026-11-06. 아래 확인은 전국의 모든 건물 표시를 보증하거나 건물의 현재 상태를 검증한 조사가 아니다.

## 바로가기와 전국 조회 재확인

2026-11-06 서울·성남·부산 바로가기의 실제 3D 렌더링을 확인했다. 세 버튼은 확대 위치의 예시이며, 건물 로더는 해당 도시로 제한하지 않는다. 바로가기 중심에서 경도·위도 각각 ±0.0025°의 WFS 응답은 아래와 같았으며 모두 HTTP 200, 잘림 없음이었다. 아래 표는 **이 작은 사각형의 응답 표본**이며 화면 전체나 도시 전체 건수가 아니다.

| 바로가기 중심 | 경도, 위도 | 유효 외곽 | 층수 기반 입체 가능 | 이름 있음 |
| --- | --- | ---: | ---: | ---: |
| 서울 | 126.9145, 37.5675 | 354 | 329 | 93 |
| 성남 | 127.1270, 37.4065 | 66 | 35 | 48 |
| 부산 | 129.1740, 35.1710 | 256 | 225 | 86 |

대구·광주·대전·제주·춘천도 응답했다. 제주·춘천의 단일 조회는 500건 제한에 걸렸으며 기존 격자 재분할이 필요하다. 전국 OSM 입력 외곽 1,372,442건 중 높이·층수가 없는 1,150,886건은 입체 자료에서 제외됐다. 포함된 221,517건의 지역별 밀도는 고르지 않다. 브이월드 층수가 없는 건물은 평면 외곽으로만 표시한다. **전국 조회 가능은 모든 건물의 입체 표시·이름·정확성을 보증하는 표현이 아니다.**

실제 건물은 줌 14 이상에서 읽는다. 넓은 화면에서는 OSM 타일 수와 브이월드 격자·요청 수 상한이 적용되며 중심 부근만 조회될 수 있다. 결과 제한·실패·높이 결측을 화면에서 구분한다. 로컬 브이월드 프록시는 GitHub Pages에 포함되지 않으므로 배포본의 가용 범위는 정적 OSM 자료와 다르다.

## 임장가자의 공개 설명

[임장가자 소개](https://imjangmap.co.kr/about)는 지도 화면의 배경과 3D 건물 출처를 국토교통부 브이월드로 밝힌다. 같은 안내에서 서울 보행망·1:1000 수치지도 기반 고도와 서울 밖 보완 고도를 구분한다. 임장가자의 공개 [지도 코드](https://imjangmap.co.kr/imjang/app.js)는 브이월드 배경지도와 건물 조회를 서버가 중계한다고 설명한다. 공개 [3D 코드](https://imjangmap.co.kr/imjang/sketch.js)의 주석은 서울 전역을 대상으로 약 1km 타일을 스트리밍하는 구조를 설명한다. 이 설명만으로 원본 서비스의 전국 건물 완전성이나 서버 내부의 가공 방법을 확인할 수는 없다.

[공공데이터포털의 공간정보오픈플랫폼 WMS/WFS 안내](https://www.data.go.kr/data/15058805/openapi.do)는 서비스 공간 범위를 대한민국 전체로 설명한다. 이는 모든 건물의 도형·층수와 최신성이 완전하다는 뜻은 아니다. 이 프로젝트는 브이월드 `도로명주소건물`의 건물 외곽과 지상층수를 조회하며, 높이는 층수 × 3m의 추정치로 구분한다. 해당 층수는 실측 높이가 아니다. 아파트 단지와 개별 건물 간 동일성은 별도 검증이 필요하다.

## 지역별 조회 표본

로컬 인증 프록시로 각 좌표 중심에서 경도·위도 각각 ±0.0025°인 사각형을 한 번씩 조회했다. 조회 시점의 응답 건수이며 지역별 전체 수치가 아니다. WFS 1.1 요청 상한은 500건이고, `matched`가 더 크면 응답이 잘린 것이다. 표시 가능한 수는 층수와 유효한 도형 등이 있는 프록시 응답 건수이다.

| 표본 중심 | 경도, 위도 | 응답 건수 / 일치 건수 | 층수 없는 항목 | 입체 표시 가능한 항목 |
| --- | --- | ---: | ---: | ---: |
| 서울 | 126.9780, 37.5665 | 150 / 150 | 44 | 106 |
| 성남 | 127.1086, 37.3947 | 31 / 31 | 4 | 27 |
| 부산 | 129.0756, 35.1796 | 247 / 247 | 122 | 125 |
| 대구 | 128.6014, 35.8714 | 424 / 424 | 73 | 351 |
| 광주 | 126.8526, 35.1595 | 19 / 19 | 5 | 14 |
| 대전 | 127.3845, 36.3504 | 58 / 58 | 1 | 57 |
| 제주 | 126.5312, 33.4996 | 500 / 983 | 378 | 122 |
| 춘천 | 127.7298, 37.8813 | 500 / 822 | 31 | 469 |

제주와 춘천의 층수 없는 항목과 표시 가능 항목은 잘린 응답의 부분 집계이므로 전체 수로 해석하면 안 된다. 건물이 밀집한 곳은 제한된 영역을 더 나누거나 공급자가 지원하는 페이징을 확인해야 하며, 실패·잘림은 화면에 구분해야 한다. 자료를 불러올 수 없거나 층수가 없는 건물은 OSM 등 별도로 확인된 데이터로 보완할 수 있지만, 출처와 데이터의 한계를 구분해야 한다.

화면 조회 로더는 500건으로 잘린 격자를 최대 두 단계로 4분할하여 재조회한다. 인접한 격자에서 중복으로 반환된 건물 ID는 제거한다. 같은 제주·춘천 표본을 포함한 정렬 격자의 재조회에서 각각 3,444건(높이 미상 2,846건), 3,072건(높이 미상 317건)을 받아 잘림·실패가 없음을 확인했다. 이 값은 위 표의 단일 사각형보다 넓은 **격자 전체**의 수치이므로 직접 비교할 수 없다. 재조회 횟수에도 상한이 있어 모든 밀집 지역의 완전성을 보장하지 않는다.

## 운영 조건과 후속 확인

- 로컬 개발 서버에서만 비공개 키를 이용해 브이월드 요청을 중계한다. 정적 GitHub Pages는 비밀키를 숨길 서버가 없으므로 이 로컬 중계를 제공하지 않는다. 배포에서 실시간 조회가 필요하면 도메인 등록, 운영 승인, 인증·요청 제한을 갖춘 별도 서버가 필요하다. 키를 브라우저나 공개 빌드에 넣지 않는다. 자세한 내용은 [키 관리와 배포](vworld-pages.md)를 참고한다.
- 제공 API와 각 자료의 보관·캐시·가공·재배포 조건 및 트래픽 한도는 서비스 용도에 따라 브이월드에 직접 확인한다. 원본 사이트의 서버 정책이나 제공처와의 개별 회신을 이 프로젝트의 허가로 간주하지 않는다.
- 자료의 누락, 높이 결측, 응답 제한, 연속 렌더링 성능과 네트워크 실패를 지역별·기기별로 점검해야 한다. 여덟 곳의 표본 응답만으로 전국 자료의 정확성이나 포괄성을 단정하지 않는다.

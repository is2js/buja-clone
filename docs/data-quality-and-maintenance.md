# 점수·지역 정합성과 유지보수 점검

점검일: 2026-11-07. 로컬 실거래 계약 기준월은 2026-10, 상권 자료 기준일은 2026-09-30입니다. 자료는 자동 갱신되지 않습니다. 로컬 Vite에서만 비공개 브이월드 키로 배경·건물을 중계하며, 정적 GitHub Pages에는 키와 프록시를 포함하지 않습니다.

## 점수

부자 원본은 가격 40, 1년 가격 흐름 25, GTX 15, 거래량 10, 전세 안정 10의 가중치를 사용합니다. 현재 1년 비교에 필요한 이전 연도 자료와 지역별 GTX 연결은 검증되지 않아 0점으로 처리하지 않습니다. `src/scoring.js`의 `buja-partial-v1`은 가격·거래량·전세가율 세 항목(원본 가중치 합 60)을 재정규화하여 같은 시도, 지역 유형, 출처 및 집계 기간의 집단에서 상대 순위를 계산합니다. 시도 내 적격 법정동이 5곳 미만이면 해당 적격 법정동만 동일 출처·기간의 전국 적격 법정동을 비교군으로 사용하는 전국 비교 점수로 계산합니다. 전국 비교 점수와 시도 비교 점수는 별도 비교군이며 지도와 상세 화면에서 범위를 표시합니다. 전국 비교 지도의 색상은 전국 순위를 나타내는 63~100점 범위를 5등분해, 적은 지역끼리 다시 순위를 매기지 않습니다. 점수 범위는 63~100입니다. 원본의 다섯 항목 점수와 직접 비교할 수 없습니다.

계산 방향은 **가격 수준이 높을수록, 최근 3개월 거래량이 많을수록, 전세가율이 낮을수록 가점**입니다. 각 지표를 비교군 안의 백분위로 바꾸고 원본 비중 40·10·10을 합계 60으로 나누어 가격 66.7%, 거래량 16.7%, 전세가율 16.7%로 적용합니다. 세 항목의 가중 합계를 다시 순위로 정렬해 `63 + 37 × 상대 순위`로 표시합니다. 이때 63은 정한 표시 하한이며, 100은 공동 최고 순위입니다. 동점은 같은 최고 순위를 사용하므로 모든 지표가 동일한 비교군은 모두 100점일 수 있습니다. 다른 시도·유형·자료·비교 범위의 점수를 절대 비교하거나, 가격이 저렴함·투자가치·안전성의 평가로 해석하지 않습니다. 원본 비중 중 60을 사용한다는 것은 신뢰도 60%를 뜻하지 않습니다.

공개판 `github-pages-public-v1`은 로컬 계약일 실거래 집계 두 파일을 빈 `status: withheld` 자료로 대체하므로 이 점수를 계산하지 않습니다. 공개판의 데이터 없음은 0점이 아니며, 로컬 점수를 샘플로 복제하지 않습니다. [공개 프로필과 제외 사유](pages-data-profile.md)를 참조하세요. 지도에서 구역을 누르면 먼저 선택·확대하며, 점수와 상세는 명시적인 정보 보기 버튼으로 엽니다.

가격 유효 표본 30건 이상, 거래 30건 이상, 전세 및 전세가율 계산에 쓰인 매매 표본 각각 30건 이상이며 비교군이 5곳 이상이어야 합니다. 2026-11-04 기준 조건을 충족한 지역은 전국 법정동 865곳, 시군구 189곳입니다. 이 중 인천은 법정동 43곳과 시군구 10곳입니다. 제주 법정동 3곳은 전국 적격 법정동 865곳과 비교한 점수이며, 나머지는 각 지역의 표본 요건에 따라 비웁니다. 나머지는 근거 부족으로 비웁니다. 상세 화면에는 표본·순위·집단 크기와 항목별 가중치를 표시합니다. 자료가 늘어나도 이 버전의 항목은 자동 변경되지 않으며, 1년 흐름과 GTX는 자료 및 연계 검증 후 별도 점수 버전으로 도입해야 합니다.

## 행정동·법정동

아파트·상업용 거래는 법정동과 시군구 기준으로 확보됐습니다. 행정동 거래를 이름이 비슷한 법정동에서 추정하면 실제 경계와 1:1이 아니므로 왜곡될 수 있습니다. 행정동에서는 직접 거래·점수를 비우고 상위 시군구 자료를 그 동의 값이 아닌 별도 참고값으로 표시합니다. 행정동 상권 업소는 공식 원천의 행정동 코드로 별도 집계합니다. 실제 행정동 거래는 거래별 정확한 주소와 해당 계약 시점의 공식 경계·행정동 연계를 확보해 재집계하기 전까지 제공하지 않습니다.

법정동 코드 생성에서 이름 접미사와 지역명 단어 수에 의존하던 결함을 수정해 세종로 등 세 곳과 세종시 33곳을 복원했습니다. 2026-11-04에 공식 코드표에서 확인한 법정 읍면동은 5,067개입니다. 전국 5,067개 중 4,998개에 2023-07-29 기반 간략화 경계를 연결했으며 나머지 69개에는 경계가 없습니다. 2023년 이후 변경된 코드 일부는 행정안전부 변경 전후 상세표로 연결했습니다. 동일하거나 연결된 코드라도 2023년 이후 실제 경계 변경이 있을 수 있습니다. 상세 방식은 `docs/legal-geography.md`를 참조합니다.

## 상권 누락 보정

경기 법정리 자료를 상위 읍·면에 포함하지 않아 122,103건이 하위 법정지역 합계에서 빠졌습니다. 공식 2026-09-30 파일을 다시 받아 실제 상위 읍·면 코드가 존재하는 경우에만 합산했습니다. 세종로 141건도 복원했습니다. 서울은 시군구와 하위 법정지역의 상권 합이 일치합니다. 경기는 부천시 소사구 1건, 화성시 동탄구 1,757건이 여전히 불일치하며 원천 코드와 최신 법정동 코드의 확인이 필요합니다. 해당 구의 법정동 상세에는 불완전 가능성 안내를 표시합니다. 이 데이터를 임의로 다른 동에 배정하지 않았습니다.

## 갱신 절차와 한계

1. 공식 [실거래가 공개시스템](https://rt.molit.go.kr/pt/xls/xls.do)에서 서울·경기의 아파트 매매·전월세와 상업·업무용 매매 6개 CSV 및 다른 14개 시도의 아파트 매매·전월세 28개 CSV를 확보하고, [상권 원본 파일](https://www.data.go.kr/data/15083033/fileData.do)을 별도로 받습니다. 원본 부자 사이트는 구현 비교 자료이며 공개된 가공물의 재배포 권한이 확인되지 않아 자동 수집 원천으로 가정하지 않습니다.
2. `docs/real-data-sources.md`의 `--as-of` 절차로 두 실거래 집계기를 실행합니다. 각각 필요한 입력·헤더·지역·기간을 검사하고 실패 시 기존 JSON을 보존합니다. JSON은 임시 파일을 거친 원자적 교체로 저장됩니다.
3. `npm run check:data`로 스냅샷 기준일·점수 산출 범위·상권 법정동과 시군구의 차이를 확인하고, `npm run test:score`와 `npm run build`를 실행합니다. 실거래와 상권 스냅샷은 별도의 수동 입력이므로 갱신 전후 기준일을 반드시 확인합니다.
4. 법정코드는 `python scripts/generate-legal.py`로 공식 코드표와 명시된 2023년 경계 가공물을 다시 대조합니다. 생성 전 유효성을 검사하지만 2023년 경계가 최신으로 바뀌는 것은 아닙니다.

실거래 집계기는 파일별·계약월별 유효 금액과 법정동 연계율을 점검하고 입력 파일 SHA-256을 진단에 남깁니다. 월별 후보가 20건 이상일 때 법정동 미연계가 10%를 넘거나 유효 금액·면적이 절반 미만이면 교체를 중단합니다. 이전 자료와 겹치는 같은 계약월의 시군구 유효 거래가 기존 30건 이상에서 90% 넘게 줄어든 경우에도 중단합니다. 정상적인 거래 급감이나 행정코드 변경도 이 기준에 걸릴 수 있으므로 원본과 코드 변경을 확인해야 하며, 자동으로 예외 처리하지 않습니다. 실패하면 기존 JSON은 보존됩니다. 이 검사는 입력의 실제 최신성이나 누락이 전혀 없음을 보증하지 않습니다.

장기 자동화에는 원천별 API 승인과 비밀 저장, 정정·해제 재조회, 호출량·실패 모니터링, 시점별 경계와 정확한 행정동 거래 매칭이 필요합니다. 외부 공개 전 국토부 다운로드 자료의 신고일 기준 공식통계 안내와 각 경계 가공물의 재배포 조건을 확인해야 합니다.

# 실제 3D 건물 사용과 브이월드 준비

검토일: 2026-11-05. 실제 지도는 전국의 OSM 건물을 기본으로 표시하고, 로컬 개발 서버에 브이월드 키가 있으면 보이는 범위에 공식 건물 외곽도 불러온다. 기재 높이 또는 층수 × 3m 추정 높이가 있는 건물은 입체로, 브이월드에서 높이가 없는 도형은 평면으로 표시한다. OSM 자료와 갱신 절차는 [3D 건물 자료](buildings-data.md), 지역별 응답과 한계는 [전국 건물 자료 확인](nationwide-building-audit.md)을 참고한다.

## 지금 확인하기

1. 프로젝트에서 `npm run dev -- --port 5189`를 실행하고 표시되는 로컬 주소를 연다. 서버가 이미 실행 중이면 이 단계는 필요 없다.
2. 지도에서 `서울 3D 건물 보기`, `성남 3D 건물 보기` 또는 `부산 3D 건물 보기`를 누르면 건물 자료가 있는 해당 시범 위치로 이동한다. 다른 곳을 볼 때는 `실제 자료`와 `3D`를 선택하고 `3D 건물`이 켜져 있는지 확인한다.
3. 시도·시군구·동을 선택하고 지도를 충분히 확대하면 그 지역의 건물을 불러온다. 세 버튼은 바로 가기 예시이며 조회 범위를 세 도시로 제한하지 않는다. 영역이 넓으면 화면 중심 부근부터 조회하며, API 제한·오류·자료 누락은 안내한다. 브이월드 도형에 층수가 없으면 평면 외곽으로 표시하고, OSM에서도 높이나 층수가 없는 건물은 입체화하지 않는다. 3D 건물은 실사 모델이 아니며 실제 모습과 높이에 차이가 날 수 있다.

브이월드와 OSM 외곽이 서로 유일하고 매우 비슷한 경우에만 화면 중복을 완화한다. OSM에 높이 기재값이 있으면 그 도형을 표시하고, 그 외에는 브이월드 층수 추정 도형을 표시한다. 양쪽 원천의 후보 도형과 높이는 유지하며 건물에 마우스를 올리면 비교값을 확인할 수 있다. 외곽 유사성은 같은 건물이라는 증명이 아니며 OSM 기재값도 실측을 보증하지 않는다. 모호한 중복은 임의 결합하지 않는다.

## 이름 표시와 지도 조작 (2026-11-06)

- 지도 도구의 `레이어`에서 공동주택·3D 건물·지형·GTX를 켜고 끈다. `추가 설정`에서 실제/가상 자료와 서울·성남·부산 바로가기를 선택한다. 보행 경사는 별도 버튼으로 시작한다.
- `크게 보기`는 같은 지도 요소를 화면 전체로 확장한다. 지역 선택과 검색은 펼쳐서 이용하며 상세 시트도 계속 사용할 수 있다. 닫으면 이전 카드 위치로 돌아간다. 중심·확대 수준과 3D 방향·기울기는 모드 전환 및 화면 크기 변경 때 유지한다.
- 2D는 드래그, 두 손가락 확대·축소, 포인터 위치를 기준으로 한 휠 확대를 지원한다. 3D는 드래그 이동·회전과 확대·축소를 사용한다. 북쪽 버튼은 방향만, 시점 초기화는 북쪽/기울기 60도로 돌린다. 선택 지역 버튼은 현재 선택한 시·군·구·동으로 지도를 맞춘다.
- 건물에 마우스를 올리면 이름을 제목으로 표시하고 해당 건물을 강조한다. 클릭하거나 모바일에서 탭하면 카드를 고정하며, 닫기·빈 지도·Esc로 해제한다. 층수와 높이는 보조 정보로 구분하고 원천·유사 외곽 비교는 카드의 `자료 정보`를 펼쳐 확인한다. 이름 결측은 `이름 미등록 건물`로 표시하며 주변 단지명을 추정하지 않는다.
- 일반 건물의 작은 이름표는 확대 수준 16 이상에서 최대 40개까지 충돌 없이 표시한다. 검증된 공동주택 대표점 라벨이 우선이며, 건물 외곽과 단지의 동일성을 이름표 배치만으로 연결하지 않는다. 큰 숫자 마커는 사용하지 않는다.
- 점수/GTX의 간단한 범례와 필수 출처는 계속 표시한다. 긴 자료 설명은 `자료·범례 자세히`에서 확인하며 조회 실패·중심 부근만 조회 같은 상태는 접히지 않는다.

화면 참고: [부자](https://buja.buildlab.im/)의 지역 점수·GTX·하단 상세, [임장가자 공개 지도 코드](https://imjangmap.co.kr/imjang/sketch.js)의 작은 건물/단지 이름표, [호갱노노](https://hogangnono.com/)의 지도 도구 그룹을 비교했다. 원본 UI를 그대로 복제하거나 원본 서비스의 가공 데이터를 가져오는 방식이 아니다. 임장가자의 서울 5m 재구성 고도와 이 프로젝트의 AWS 공개 DEM은 서로 다르므로 같은 지형 상세를 보장하지 않는다.

검증 기록: 2026-11-06 관련 JavaScript 검사 70개와 정적 빌드가 통과했다. 데스크톱 및 390×844 화면에서 크게 보기·복귀, 레이어 설정, 건물 이름표·클릭 카드·자료 정보·Esc, 2D↔3D 방향 유지와 경기 시→구→동 탐색을 확인했다. 보행 좌표와 핀치·휠의 좌표 불변성은 자동 검사로 확인했다. WFS/배경 타일 실패 및 DEM 결측은 기존 자동 검사와 코드로 확인했으며, 실제 MapLibre 화면의 네트워크를 강제로 끊는 통합 검사는 수행하지 않았다. 정적 빌드의 MapLibre 청크 용량 경고는 남아 있다.

## 브이월드 연동을 위한 사용자 준비

**로컬 Vite 개발 서버에 `.env.local` 키가 있으면 브이월드 배경과 WFS 도로명주소건물을 사용한다. 정적 GitHub Pages 및 Vite 미리보기에서는 OSM으로 동작하며 배포용 비공개 프록시는 별도 구현이 필요하다.** 브이월드 결과가 500건으로 잘리면 제한된 깊이까지 구역을 나누어 재조회한다. 일부 조회가 실패하거나 한도에 걸리면 얻은 건물과 OSM을 유지하고 화면에 표시한다. 이미 확인한 응답은 브라우저 메모리에 2분 동안만 저장한다. 제공자의 캐시·서비스 이용 조건은 배포 전에 확인해야 한다.

1. [브이월드](https://www.vworld.kr/)에 가입하고 로그인한다. [브이월드 교육자료](https://www.spacein.kr/data/bbs/279/%5B3_4%EC%B0%A8%EC%8B%9C%5D_%EB%B8%8C%EC%9D%B4%EC%9B%94%EB%93%9C%EC%84%9C%EB%B9%84%EC%8A%A4%ED%99%9C%EC%9A%A9%EB%B0%8F%EA%B0%9C%EB%B0%9C.pdf)는 `마이포털 → 나의 오픈API → 인증키 관리 → 발급하기` 순서를 안내한다. 발급 화면의 현재 절차를 우선한다.
2. 서비스명과 실제 사용할 URL을 입력하고, 건물 외곽 및 속성에 적합한 데이터 API 또는 WMS/WFS를 선택한다. 사용할 레이어와 기능이 정해지면 정확한 선택 항목을 확인해야 한다. 로컬 127.0.0.1 주소와 포트의 허용 여부는 발급 화면이나 제공처에서 확인한다. GitHub Pages로 배포한다면 실제 Pages URL도 검토한다.
3. 개발키와 운영키의 최신 유효기간·사용량·운영 심사, 브라우저 호출 가능 여부(CORS), 데이터 저장·캐시·재배포 조건을 제공처에 확인한다. 타 서비스에서 사용한 키나 캐시 규칙을 그대로 전제하지 않는다.
4. 인증키는 채팅이나 공개 저장소에 붙여넣지 않는다. 추후 구현 방식이 확정되면 도메인 제한 키 또는 비공개 수집 환경을 마련한다. 정적 페이지에서 브라우저로 직접 호출하는 키는 방문자가 볼 수 있어 완전한 비밀로 취급할 수 없다.

브이월드 연결 시에도 요청 실패와 자료 결측을 구분하고, 층수 기반 높이는 추정값이라고 표시해야 한다. 3D 고해상도 실측 지형은 별도 자료다.
